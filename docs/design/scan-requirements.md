# Режимы сканирования: требования пользователя

**Статус: утверждён пользователем 16 ноября 2026 года.**

Документ собирает требования, которые обсуждались в сессиях проекта Anime.
Он не подтверждает, что нынешний сканер им соответствует. Неопределённости и
вопросы реализации, отмеченные ниже, сохраняются. Обозначения источников в
квадратных скобках соответствуют списку сессий в конце документа.

## Назначение

Пользовательский скан обновляет общий каталог через подключение пользователя.
Это позволяет получать обновления AnimeGO, когда обращение с серверного хостинга
затруднено. Любой пользователь сайта должен иметь возможность запустить скан;
найденные и сохранённые изменения становятся доступны всем пользователям. Для
каждой добавленной серии нужно сохранять, какой пользователь её добавил. Это
нужно в том числе для возможной будущей очистки данных конкретного пользователя;
реализацию отдельного инструмента очистки пользователь тогда отложил. [И1]

Предусмотрены три режима: **быстрый**, **расширенный (Extended)** и
**полный (Full)**. Быстрый проверяет незавершённые личные тайтлы и случайную
выборку незавершённых; расширенный проверяет все незавершённые; полный проверяет весь
каталог и ищет новые тайтлы. Уточнение от 16 ноября заменяет прежнее описание
Extended как простого отбора по дате изменения. [И1, И2, И3, И15]

## Как определять завершённость для сканирования

Под «завершённым» для отбора понимается тайтл, который либо достоверно
завершил выпуск, либо долго не менялся по достаточно надёжным данным. Это
рабочая классификация сканера: отсутствие изменений не доказывает, что выпуск
официально закончился, поэтому исходный статус выпуска и причина отнесения к
завершённым хранятся отдельно. Статусы и даты нужно актуализировать при
проверках, не подменяя их датой последнего обращения сканера. [И15]

**Начальный расчёт:**

1. Если источник достоверно сообщает, что выпуск завершён, учитывать этот
   признак. Дата окончания и явный статус могут служить подтверждением только
   тогда, когда известны их смысл и надёжность; предполагаемые даты не выдавать
   за факт. Статусы связанных источников сверять: если один подтверждённо
   сообщает, что выпуск продолжается, не считать выпуск завершённым только
   на основании противоречащего ему статуса другого источника. При этом
   длительное подтверждённое отсутствие изменений оценивается отдельно.
2. При отсутствии подтверждённого завершения отнести тайтл к давно не
   обновлявшимся, если надёжные данные или собственные успешные проверки
   показывают отсутствие изменений **не менее одного календарного месяца**.
   Учитывать изменения серий, озвучек и плееров связанных вариантов; при
   определении срока использовать самую позднюю подтверждённую дату изменения.
   Месяц без изменений — правило отбора, а не доказательство того, что
   обновлений больше не будет. Проверка без изменений сама по себе не является
   датой изменения и не сбрасывает срок наблюдения.
3. Если источник не сообщает надёжной даты изменения, первая успешная
   достаточно полная проверка сохраняет состояние содержимого и дату начала
   наблюдения. Через месяц или позднее повторная успешная проверка сравнивает
   его с сохранённым состоянием: если изменений нет, тайтл можно считать
   завершённым для отбора. Если обнаружено изменение, сохранить новое состояние
   и начать отсчёт месяца заново с момента его обнаружения. Если исходная дата
   изменения достоверно известна, её можно учитывать наряду с наблюдениями.
   Ошибка, недоступный источник или неполная проверка не подтверждают отсутствие
   изменений: до успешной проверки сохранять неизвестное состояние и включать
   тайтл в Extended. Результат сравнения подтверждает отсутствие обнаруженных
   изменений между проверками, но не исключает промежуточные изменения или
   изменения вне охвата проверенного источника.
4. Если появился надёжный признак нового содержимого или изменился статус
   выпуска, пересчитать классификацию; при новом содержимом вернуть тайтл в
   отбор Extended, если нет подтверждённого завершения выпуска. Завершение
   выпуска не означает, что не может появиться новая
   озвучка или плеер; полный скан проверяет такие тайтлы.

Реализация должна проверить, какие данные каждого источника действительно
покрывают серии, озвучки и плееры. Если источник этого не гарантирует, факт
неизменности этих данных нельзя выводить только из даты страницы.

## Быстрый скан

### Личные тайтлы

1. Проверяются незавершённые тайтлы пользователя из **избранного** и **«Смотрю»**. Если
   один тайтл входит в обе группы, он не должен проверяться дважды только
   из-за этого. Для личной части пользователь просил проверять *всё*, а не
   ограничивать её заранее заданным числом мест. По уточнению пользователя
   завершённые личные тайтлы пропускаются; при неизвестной классификации
   тайтл остаётся в проверке. [И3, И15]
2. Личные тайтлы проверяются в первую очередь. Если источник недоступен или
   проверить тайтл не удалось, результат должен сообщать об этом, а не считать
   такой тайтл успешно обновлённым.

После проверки реального быстрого скана пользователь уточнил, что завершённые
из избранного тоже должны пропускаться. Это уточнение заменяет предыдущее
предположение, что личные тайтлы проверяются независимо от завершённости.
[И4, И15]

### Дополнительная выборка

1. Помимо личных тайтлов, каждый быстрый скан проверяет несколько
   дополнительных случайно выбранных тайтлов, чтобы и остальной каталог не
   слишком отставал без частых полных сканов. [И3]
2. Предпочтительны тайтлы, у которых недавно появлялись обновления, а также
   те, которые давно не проверяли. Пользователь согласился на случайный выбор
   с такими приоритетами. В дополнительную выборку входят только незавершённые
   и тайтлы с неизвестной классификацией; завершённые в неё не попадают. [И3, И15]
3. В исходном описании пользователь также просил, чтобы случайные тайтлы
   отличались от запуска к запуску. При обсуждении алгоритма агент пояснил,
   что взвешенная случайность сама по себе не гарантирует это; пользователь
   одобрил случайность с приоритетами, не уточнив правило повторов. Это
   точное правило повторов остаётся открытым. [И3]

Конкретное количество дополнительных тайтлов, веса, интервалы и точный
алгоритм пользователь не задал. Восемь тайтлов и формула весов встречаются
в описании реализации, но не являются здесь самостоятельными требованиями.

## Расширенный скан — Extended

Extended проверяет **все незавершённые тайтлы**, независимо от избранного и
статуса просмотра пользователя. Для каждого выбранного тайтла учитываются все
его имеющиеся источники. Тайтлы, признанные завершёнными по правилам выше, из
этого режима исключаются; при неизвестной классификации тайтл включается.
Поиск новых тайтлов сохраняется в пределах разрешённого охвата источников. [И15]

Этот режим экономит время за счёт отбора, поэтому не гарантирует актуальность
завершённых тайтлов или всей базы. Результат не должен утверждать обратное.

## Полный скан — Full

### Охват существующего каталога

Цель полного скана — актуализировать весь существующий каталог по всем
используемым источникам и обнаружить новые тайтлы в пределах разрешённого
охвата источников. У одной карточки может быть несколько источников: каждый
должен быть учтён, даже если он скрыт за объединённой карточкой. Это включает
новые серии, озвучки и плееры у уже известных тайтлов. [И3, И15]

При этом не нужно подробно загружать каждый старый тайтл при каждом запуске:
одна такая проверка занимает заметное время и создаёт запросы к источнику.
При полном скане нужно проверить все тайтлы и все доступные источники, не
исключая их только из-за возраста, отсутствующей даты или статуса выпуска.
Исключение допустимо, только если достоверно известно, что у конкретного
источника после последней проверки нет обновлений. Сам по себе старый статус
или старая дата в нашей базе такого подтверждения не дают. [И15]

### Порядок работы

Это порядок работы по требованиям, а не описание уже выпущенного поведения.

Статус выпуска каждого тайтла нужно актуализировать по доступным данным
источников: различать выходящие и завершённые тайтлы и сохранять дату
окончания, если её удалось достоверно установить. Сверять связанные источники
одной карточки и не придумывать статус или дату при отсутствии подтверждения.
Завершение выпуска снижает приоритет проверки, но само по себе не доказывает,
что позднее не появилась новая озвучка или плеер. [И15]

1. Сначала получить доступные сводные признаки изменений и новые карточки у
   каждого источника: например, его список обновлений, API или карту страниц.
   Сохранять дату изменения источника отдельно от даты нашей проверки, а также
   знать, с каким признаком проводилась последняя успешная подробная проверка.
   Проверка без нового содержимого не должна сама делать тайтл «свежим». Для
   поиска новых тайтлов использовать общий список только после проверки его
   полноты; иначе обходить страницы каталога с возможностью продолжения.
2. Подробно проверить новые тайтлы и те существующие источники, где найден
   признак изменения: новую серию, озвучку, плеер или обновление страницы,
   которое может их затрагивать. Новое изменение должно попадать в скан даже
   после долгого периода без обновлений.
3. Если достоверный для данного вида содержимого признак подтверждает, что
   источник не изменился со времени последней успешной проверки, повторно
   загружать его не нужно. Дату страницы можно считать таким подтверждением
   только после проверки, что она действительно меняется и при изменении
   видео или плееров; одна её давность этого не доказывает.
4. При отсутствии такого признака полный скан проверяет источник подробно,
   в том числе если дата отсутствует. Он может занять значительно больше
   времени, чем расширенный; предложенный ранее предел в 20 старых источников
   к полному режиму не применяется.
5. Скан с недоступными источниками, ошибками или непроверенным остатком не
   должен сообщать, что вся база полностью актуальна. Нужно показать эти
   ограничения и позволить продолжить проверку.

Недоступность одного источника не должна мешать обработать остальные. В конце
нужно различать найденные и сохранённые изменения, источники без изменений по
достоверному признаку, ошибки и оставшиеся непроверенные источники. Остановка
скана не должна терять уже сохранённые изменения или позицию проверки по кругу.

Для быстрого скана незавершённые личные тайтлы имеют приоритет перед этой
экономией; при неизвестной классификации их также проверяют, учитывая все их
источники. Если достоверный сводный признак подтверждает, что источник личного
тайтла не менялся после последней успешной проверки, лишняя подробная загрузка
не нужна. Для обоих режимов
стоит измерять число запросов и длительность по источникам, избегать лишних
повторов и ограничивать нагрузку. Запросы через браузер пользователя всё равно
видны источнику; сокращение их числа не делает сканирование невидимым.

### Соответствие реализации

Документ описывает желаемое поведение. После уточнения 16 ноября требуется
отдельно проверить реализацию, особенно классификацию завершённых тайтлов и
отбор Extended. Запись требований сама по себе не меняет сайт или расширение.

### Новые тайтлы AnimeGO

Если полный скан находит отсутствующий в каталоге тайтл, у которого появилось
видео, он должен: [И2]

1. Добавить тайтл и доступные для воспроизведения серии.
2. Перенести доступные из источника сведения автоматически, без ИИ и без
   выдуманных данных.
3. Пометить карточку как неполную, **«Требует оформления»**, чтобы позже её
   можно было найти и дооформить, в том числе с помощью ИИ: уточнить описание,
   собрать сведения и связать тайтл с другими частями франшизы.
4. При последующих сканах обновлять видео, сохраняя уже выполненное оформление
   карточки и не сбрасывая её готовность без основания. Эту схему пользователь
   согласовал после объяснения агента. [И2]

Требование прямо описывает добавление тайтлов **с видео**. Что делать с
анонсами без доступного видео, в просмотренных сообщениях отдельно для этого
режима не согласовано; действующее руководство описывает каталог с проверяемым
видео как условие добавления. [И2, И14]

### Kinogoo и другие источники

Сканер должен обновлять уже добавленные карточки Kinogoo. Создавать новые
карточки Kinogoo автоматически сканером пользователь не просил и прямо
исключил; отдельное ручное добавление выбранного сериала возможно по его
поручению. [И6]

В проекте также используется YummyAnime. Требование полного скана охватить
все источники относится к результату для каталога; требуется проверить,
как в этом результате участвует YummyAnime. В частности, наличие отдельной
синхронизации само по себе ещё не доказывает, что запуск полного скана
обновляет этот источник. [И3, И14]

## Общие требования к использованию и результатам

### Запуск и интерфейс

- На сайте должна быть обычная кнопка запуска скана и доступ к трём режимам.
  Первоначально пользователь предложил кнопку Scan с меню выбора режима. [И1]
- После открытия страницы расширения можно выбрать любой из трёх режимов
  и запустить следующий скан на той же странице после предыдущего, не
  закрывая её и не возвращаясь каждый раз к кнопке сайта. [И7, И8]
- Оформление страницы сканера должно соответствовать стилю основного сайта. [И7]
- Сканер должен работать в Chrome и Safari; если расширение отсутствует,
  пользователю должен быть доступен подходящий для браузера способ установки.
  Пользователь также просил обеспечить удобное обновление установленной
  устаревшей версии расширения. [И9, И6]
- Состояние запуска должно отражаться корректно: кнопка не должна оставаться
  в состоянии сканирования после его завершения; повторное нажатие на быстрый
  скан в расширении должно запускать новую проверку. [И8, И10]

### Данные и видимость обновлений

- Новые серии должны находиться и появляться в каталоге с работающими
  источниками воспроизведения. Пользователь также просил не пропускать
  дробные спецвыпуски и проверить другие возможные пропуски при импорте. [И11]
- Когда сканер находит новую серию, данные в других открытых браузерах должны
  обновляться автоматически. Пользователь задал интервал опроса **30 секунд**
  и попросил сделать его достаточно лёгким для сервера и браузера. [И12]
- В исходной идее пользователь подчёркивал добавление новых серий и сохранение
  автора добавления. Позднее он попросил полностью актуализировать источники,
  а для новых карточек согласовал защиту уже выполненного оформления. Границы
  изменения существующих ссылок и метаданных нужно уточнить: эти пожелания не
  задают сами по себе подробного правила для каждого поля. [И1, И2, И3]
- Ошибки источников нужно разбирать и исправлять, а не считать признаком
  успешной проверки. В одном конкретном случае пользователь отдельно попросил
  убрать ссылки на действительно удалённые карточки AnimeGO, но сохранить
  работающие видео и данные альтернативного источника. Это поручение не
  задаёт общего правила удалять данные при любом ответе 404. [И3, И7]

## Примеры для проверки

Это предложенные примеры проверки смысла требований, а не утверждение, что
они уже проходят в приложении.

| Ситуация | Ожидаемый результат |
| --- | --- |
| Тайтл есть и в избранном, и в «Смотрю», его выпуск ещё идёт. | Быстрый скан включает его в личную часть один раз. |
| Любимый сериал завершился больше месяца назад. | Быстрый скан пропускает его; полный скан проверяет. |
| Два подходящих дополнительных тайтла различаются давностью проверки и недавними изменениями. | Выбор учитывает оба фактора, а не только равномерную случайность. |
| Надёжный признак показывает, что старый источник не менялся после последней успешной проверки. | Полный скан не загружает его подробно без необходимости. |
| После долгого перерыва источник сообщает о новой серии. | Полный скан проверяет изменение, даже если прежняя дата в нашей базе старая. |
| Дата обновления неизвестна, статус выпуска не подтверждён и надёжного признака нет. | Тайтл включается в Extended и Full; дата не подменяется предположением. |
| Тайтл не в личных списках, выпуск продолжается, а последняя известная дата изменения старая. | Extended проверяет тайтл, если длительное отсутствие обновлений не подтверждено. |
| Достоверно подтверждено, что выпуск завершён или при проверках не обнаружено изменений за месяц. | Быстрый и Extended исключают тайтл; Full всё равно его проверяет. |
| У тайтла нет даты обновления, а первая успешная проверка проведена сегодня. | Сохранить состояние и начать наблюдение; до повторной проверки через месяц не считать его завершённым из-за отсутствия изменений. |
| Через месяц повторная успешная проверка не нашла изменений. | Считать тайтл завершённым для отбора Extended; карточку и её данные не удалять. |
| В период наблюдения найдена новая озвучка. | Сохранить новое состояние и начать месячный отсчёт заново. |
| Через месяц источник не отвечает. | Не считать ошибку подтверждением неизменности; оставить тайтл в Extended до успешной проверки. |
| Источник сообщил о новом содержимом после периода без обновлений, выпуск не подтверждённо завершён. | Классификация пересчитывается; тайтл снова участвует в Extended. |
| Тайтл завершился давно, но источник обновился после последней проверки. | Полный скан проверяет источник независимо от даты завершения выпуска. |
| У подходящей для полного скана карточки несколько источников. | Полный скан обеспечивает согласованный охват этих источников, а не только одного выбранного варианта. |
| Источник сообщает о новой озвучке или плеере у известной серии. | Полный скан проверяет и сохраняет обновление; при отсутствии надёжного признака не утверждает, что оно не появилось. |
| Источник недоступен во время скана. | Результат показывает непроверенный источник и не заявляет полной актуальности базы. |
| В AnimeGO появился новый тайтл с видео. | Полный скан добавляет доступное видео и карточку с автоматически полученными данными и отметкой о необходимости оформления. |
| Новая карточка уже была дооформлена. | Последующий скан не уничтожает выполненное оформление при обновлении видео. |
| В Kinogoo появилась новая карточка, которую пользователь не добавлял. | Сканер не создаёт её автоматически; существующие добавленные карточки остаются в области проверки. |
| Скан завершён, пользователь запускает следующий из страницы расширения. | Новый скан можно запустить без закрытия страницы и возврата на сайт. |
| Один пользователь добавил сканом серию, другой держит каталог открытым. | Можно определить автора добавления; второй браузер получает обновление через механизм опроса. |

## Что проверить при реализации

1. **Надёжность признаков.** Для каждого источника нужно проверить, покрывают
   ли его даты и списки изменения серий, озвучек и плееров. Пока это не
   установлено, они не подтверждают отсутствие изменений.
2. **Источники без надёжных дат.** Полный режим должен их проверять, а не
   ограничиваться частью на один запуск. Измерить длительность и число запросов;
   недоступные источники и ошибки показывать отдельно.
3. **Дополнительная выборка быстрого скана.** В качестве начального решения
   сохранить до восьми дополнительных незавершённых тайтлов, отдавая предпочтение выходящим
   и давно не проверенным. При достаточном числе кандидатов не повторять
   дополнительную выборку предыдущего запуска; число и веса затем оценить по
   результатам. Открытый сейчас тайтл сохраняет существующий приоритет.
4. **Источники личного тайтла.** Проверять все имеющиеся источники; если
   надёжный общий признак подтверждает отсутствие изменений, подробный запрос
   можно пропустить. Новые озвучки и плееры входят в обновление.
5. **Границы изменений.** Сохранять выполненное оформление, не удалять данные
   из-за одной ошибки источника и добавлять новые карточки при наличии видео;
   остальные правила обновления полей и ссылок проверить при разработке.
6. **Статус выпуска Kinogoo.** Использовать только подтверждённые данные; при
   отсутствии надёжной даты не выдумывать её. [И13]
